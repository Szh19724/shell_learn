# 04 STM32工程建立-程序下载原理

> 本课整理自 `STM32/4.STM32工程建立-程序下载原理.zip → 04工程建立，程序下载原理/STM32工程建立，程序下载原理.pdf`(共 46 页)。返回 [[STM32学习目录|📑 STM32学习目录]]。

## 本章要点

- STM32 通过 `BOOT[1:0]` 引脚在主 Flash / 系统存储器 / 嵌入式 SRAM 三种自举模式间选择启动空间;串口下载走的是系统存储器里出厂预置的 ISP 自举程序(USART1/USART3/CAN2/USB OTG FS)。
- 用 FlyMcu 串口下载:选对串口(115200bps)→ 选 `.hex` 文件 → 勾选"编程前重装文件" → 点"开始编程";下载前 BOOT 跳线置 USART 模式,下载完接回主 Flash 模式运行。
- 标准库工程 = 手动搭文件夹结构(User/Libraries/Projecat…)+ 从固件包 `stsw-stm32065_v1-9-0`(V1.9.0)拷贝模板文件与驱动库 + 在 Keil5 中建组、填全局宏与头文件路径。
- 标准库必须换用 V5 编译器:手动安装 `ARMCompiler_506` 到 `ARM\ARMCOMPLIER506`,在 Manage Project Items 的 Folders/Extensions 页添加;Global Define 填 `USE_STDPERIPH_DRIVER,STM32F40_41xxx,`(注意用英文逗号)。
- 当前芯片不支持的驱动文件取消 `Include in Target Build` 或直接 Remove File;标准库有 bug,需给 `stm32f4xx.h` 解除只读并注释掉 Legacy aliases 段的重复宏。
- HAL 库工程用 STM32CubeMX 生成:选芯片 STM32F407ZGT6 → 配时钟与引脚 → Project Manager 选 IDE → GENERATE CODE;用户代码写在 `USER CODE BEGIN/END` 之间,点灯用 `HAL_GPIO_WritePin`。

## 下载原理

> 📄 原课件 p.1

页面下半部分是参考手册《自举配置》一节的摘录,要点转写如下。

**存储器映射与自举机制**:存储器采用固定的存储器映射,代码区域起始地址为 `0x0000 0000`(通过 ICode/DCode 总线访问),而数据区域起始地址为 `0x2000 0000`(通过系统总线访问)。Cortex™-M4F CPU 始终通过 ICode 总线获取复位向量,这意味着只有代码区域(通常为 Flash)可以提供自举空间。STM32F4xx 微控制器实施一种特殊机制,可以从其它存储器(如内部 SRAM)进行自举。

在 STM32F4xx 中,可通过 `BOOT[1:0]` 引脚选择三种不同的自举模式,如表 3 所示。

**表 3. 自举模式**

| 自举模式选择引脚 BOOT1 | 自举模式选择引脚 BOOT0 | 自举模式 | 自举空间 |
| --- | --- | --- | --- |
| x | 0 | 主 Flash | 选择主 Flash 作为自举空间 |
| 0 | 1 | 系统存储器 | 选择系统存储器作为自举空间 |
| 1 | 1 | 嵌入式 SRAM | 选择嵌入式 SRAM 作为自举空间 |

复位后,在 SYSCLK 的第四个上升沿锁存 BOOT 引脚的值。复位后,用户可以通过设置 BOOT1 和 BOOT0 引脚来选择需要的自举模式。

BOOT0 为专用引脚,而 BOOT1 则与 GPIO 引脚共用。一旦完成对 BOOT1 的采样,相应 GPIO 引脚即进入空闲状态,可用于其它用途。

器件退出待机模式时,还会对 BOOT 引脚重新采样。因此,当器件处于待机模式时,这些引脚必须保持所需的自举模式配置。这样的启动延迟结束后,CPU 将从地址 `0x0000 0000` 获取栈顶值,然后从始于 `0x0000 0004` 的自举存储器开始执行代码。

> 注意:如果器件从 SRAM 自举,在应用程序初始化代码中,需要使用 NVIC 异常及中断向量表和偏移寄存器来重新分配 SRAM 中的向量表。

**嵌入式自举程序**:嵌入式在自举程序模式用于通过以下串行接口重新编程 Flash:

- USART1(PA9/PA10)
- USART3(PB10/11 和 PC10/11)
- CAN2(PB5/13)
- USB OTG FS(PA11/12)从设备模式(DFU;器件固件升级)

USART 外设以内部 16 MHz 振荡器(HSI)频率运行,而 CAN 和 USB OTG FS 则需要相当于是 1 MHz 整数(4 MHz 到 26 MHz 之间)的外部时钟(HSE)频率。嵌入式自举程序代码位于系统存储器中,在芯片生产期间由 ST 编程(详见应用笔记 AN2606)。

**物理重映射**:选择自举引脚后,应用程序软件可以将某些存储器设定为从代码空间进行访问(这样,可通过 ICode 总线而非 System 总线执行代码)。这样的修改通过在 SYSCFG 控制器中编写 SYSCFG 存储器重映射寄存器(SYSCFG_MEMRMP)来实现。因此可重映射以下存储器:主 Flash、系统存储器、嵌入式 SRAM1(112 KB)、FSMC 块 1(NOR/PSRAM 1 和 2)。

**表 4. 存储器映射与自举模式/物理重映射**

| 地址 | 主 Flash 中的自举/重映射 | 嵌入式 SRAM 中的自举/重映射 | 系统存储器中的自举/重映射 | FSMC 中的重映射 |
| --- | --- | --- | --- | --- |
| 0x2002 0000 - 0x2002 FFFF | SRAM3 (64 KB) | SRAM3 (64 KB) | SRAM3 (64 KB) | SRAM3 (64 KB) |
| 0x2001 0000 - 0x2001 FFFF | SRAM2 (16 KB) | SRAM2 (16 KB) | SRAM2 (16 KB) | SRAM2 (16 KB) |
| 0x2000 0000 - 0x2000 FFFF | SRAM1 (112 KB) | SRAM1 (112 KB) | SRAM1 (112 KB) | SRAM1 (112 KB) |
| 0x1FFF 0000 - 0x1FFF 77FF | 系统存储器 | 系统存储器 | 系统存储器 | 系统存储器 |
| 0x0810 0000 - 0x08FF FFFF | 保留 | 保留 | 保留 | 保留 |
| 0x0800 0000 - 0x080F FFFF | Flash | Flash | Flash | Flash |
| 0x0400 0000 - 0x07FF FFFF | 保留 | 保留 | 保留 | FSMC 块 1 NOR/PSRAM 2(使用别名) |
| 0x0000 0000 - 0x03FF FFFF | Flash (1 MB) 使用别名 | SRAM1 (112 KB) 使用别名 | 系统存储器 (30 KB) 使用别名 | FSMC 块 1 NOR/PSRAM 1(使用别名) |

注:SRAM1 仅用于 STM32F42xxx 和 STM32F43xxx;在地址 0x0000 0000 处重映射 FSMC 块 1 仅能重映射块 1 存储控制器的前两个区域,重映射模式下 CPU 可通过 ICode 总线访问外部存储器以提高性能;即使在自举存储器中使用别名,相关存储器仍可通过其初始存储空间进行访问。

### 标准库开发方式

> 📄 原课件 p.36–37

配置好 V5 编译器后(Options for Target → Target 页 ARM Compiler 下拉中即可选到 V5.06 update 7),就可以按标准库方式开发。课件给出点灯示例:使能 GPIOE 时钟,把 PE3、PE4 配置为推挽输出、上拉、低速,初始化后输出低电平点灯。

![魔法棒 Target 页可选择 V5.06 编译器后编译标准库工程](assets/04-STM32工程建立-程序下载原理/p36_1.png)

```c
#include "stm32f4xx.h"

int main()
{
    //时钟使能
    RCC_AHB1PeriphClockCmd(RCC_AHB1Periph_GPIOE,ENABLE);
    //配置功能
    GPIO_InitTypeDef ledstruct ;
    ledstruct.GPIO_Mode = GPIO_Mode_OUT ;
    ledstruct.GPIO_OType = GPIO_OType_PP ;
    ledstruct.GPIO_Pin = GPIO_Pin_4 | GPIO_Pin_3 ;
    ledstruct.GPIO_PuPd = GPIO_PuPd_UP ;
    ledstruct.GPIO_Speed = GPIO_Low_Speed ;

    GPIO_Init(GPIOE,&ledstruct);

    GPIO_ResetBits(GPIOE,GPIO_Pin_3|GPIO_Pin_4);

    while(1)
    {
    }
    return 0 ;
}
```

使用到的函数:`HAL_GPIO_WritePin` 的说明(截图转写):

```c
/**
 * @brief  设置或清除所选数据端口的位。
 *
 * @注意   此功能通过使用 GPIOx_BSRR 寄存器来实现原子式的读/写操作。这样一来,在读取和写
 *         入操作之间就不会出现中断请求的情况,从而避免了可能出现的中断问题。
 *
 * @参数 GPIOx, 其中 x 可以是 (A 至 K), 用于选择适用于 STM32F429X 设备的 GPIO 外设,
 *       或者 x 可以是 (&至 I), 用于选择适用于 ST132F40XX 和 ST32F427X 设备的 GPIO 外设。
 *       GPIO_Pin 指定要写入的端口位。
 * @param
 * 此参数可以是 GPIO_PIN_x 形式的值,其中 x 可以取值 (0 到 15)。@参数 PinState 指
 * 定要写入选定定位的值。此参数可以是 GPIO_PinState 枚举值中的任一值:
 *         @参数 GPIO引脚复位: 用于清除端口引脚@参数 GPIO引脚设置
 *         : 用于设置端口引脚
 * @返回值 无
 */
```

![HAL_GPIO_WritePin 函数说明(通过 GPIOx_BSRR 原子操作)](assets/04-STM32工程建立-程序下载原理/p45_2.png)

## 小结与下一步

- STM32 靠 `BOOT[1:0]` 选择主 Flash / 系统存储器 / 嵌入式 SRAM 三种自举模式;串口下载走系统存储器 ISP 自举程序,FlyMcu 按"选串口 → 选 hex → 勾编程前重装 → 开始编程"操作,下载用 USART 模式、运行接回主 Flash 模式。
- 标准库工程 = 手动文件夹结构 + 固件包模板/驱动拷贝 + Keil 建组添加文件 + 全局宏与头文件路径 + 屏蔽不支持的文件 + 修 `stm32f4xx.h` 的 bug + 换用 ARM Compiler V5.06。
- HAL 库工程用 STM32CubeMX 生成:选芯片 → 配时钟/引脚 → 生成工程;用户代码写在 `USER CODE BEGIN/END` 之间,点灯用 `HAL_GPIO_WritePin` 控制 PE3/PE4。
