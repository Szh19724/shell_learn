## 答题约定

- 脚本默认 `___` 表示未作答，运行会打印每题的参考答案，**不判失败**；
- 作答后运行，逐题显示 `[通过]` / `[失败]`，失败会给出你的输出与期望输出的对比；
- 全部通过时退出码为 0，可直接串进 CI 或脚本里自测。

## 做题顺序建议

1. `01` —— 把 10 个元字符的含义用 `grep -E` 亲手试一遍；
2. `02` —— 走一遍教材主线：粗匹配 → 每段 1~3 位 → 精简写法 → 统计/打码，体会"正则只管形状"；
3. `03` —— 用 shell 把网址规则写熟（含负面样本：缺路径、路径不是 `/cn/`、不是 `www.` 开头）；
4. `match_url.c` —— 把同样的规则搬进 C，重点掌握四个 API 的参数与返回值。

## 几个容易踩的坑

- **子串匹配**：`grep` 匹配的是"包含"，`a{3}` 在 `aaaa` 里也能命中；要"整行等于"得加 `^$`（见 01 进阶题）。
- **正则不校验取值**：`999.999.999.999`、`10.0.0.256` 形状都合法，判断 0~255 要用程序或 `grep -P`（见 02 进阶题）。
- **贪婪与截断**：`192.168.31.1015` 用 `{1,3}` 只会截出 `192.168.31.101`，多出的 `5` 留在原地 —— 这就是"正则只管形状"。
- **C 里的转义**：正则里的 `\.` 写进 C 字符串要变成 `\\.`；`{2,}` 在 ERE 里直接用，不用加反斜杠。
- **匹配多个**：`regexec` 每次只返回第一个命中，把游标挪到 `rm_eo` 处循环调用才能找出全部（见 `match_url.c` 第 3 步注释）。
